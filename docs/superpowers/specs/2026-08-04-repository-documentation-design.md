# Repository Documentation Design

## Objective

Prepare the current Tencent Cloud seckill project for publication at
`https://github.com/kkkksad/tenxunyun.git`. A new user should be able to
install dependencies, obtain cookies, configure the target, run the script,
understand its output, and troubleshoot common failures without reading the
source first.

## Scope

The publication commit will include:

- the current `get_cookies.py` login and cookie refresh flow;
- the current `snap_up_server.py` activity, Ubuntu 24.04, CSRF, timing, region,
  concurrency, and retry behavior;
- `test_retry_window.py`;
- a rewritten Chinese `README.md`;
- a minimal `requirements.txt`;
- expanded Git ignore rules for cookies, virtual environments, and Python
  caches.

No cookie values, account identifiers, credentials, generated bytecode, or
local virtual environments will be committed.

## Documentation Structure

The README will use one self-contained document rather than a multi-page docs
tree. It will contain:

1. project purpose, supported target, and prominent risk notice;
2. current defaults: activity, Ubuntu 24.04 LTS, product type, and the valid
   Guangzhou, Shanghai, and Beijing region IDs;
3. prerequisites and virtual-environment installation for Windows and
   Linux/macOS;
4. Playwright Chromium installation;
5. cookie refresh and automatic CSRF derivation;
6. configuration of sale time, early-start offset, retry window, interval, and
   regions;
7. exact run and test commands;
8. output interpretation and troubleshooting for missing dependencies,
   incomplete cookies, CSRF errors, not-started responses, no stock, time
   display, and direct `.py` execution on Windows;
9. security, account eligibility, rate limiting, real-order, duplicate-order,
   and no-guarantee warnings;
10. file layout and a concise description of the request flow.

The README will describe actual behavior rather than obsolete manual CSRF or
inventory-first behavior from the existing document.

## Repository Changes

`requirements.txt` will list `requests` and `playwright`. Browser installation
will remain a separate documented command because Playwright does not install
Chromium as part of `pip install`.

`.gitignore` will retain all existing secret exclusions and add Python cache,
test cache, and virtual-environment entries. `cookies.json` remains excluded.

The script's region display labels may be corrected to match the activity
page's authoritative mapping without changing the submitted numeric IDs:

- `1`: Guangzhou (`ap-guangzhou`)
- `4`: Shanghai (`ap-shanghai`)
- `8`: Beijing (`ap-beijing`)

No unrelated performance redesign is included in this publication task.

## Verification

Before publication:

- compile both Python scripts;
- run `test_retry_window.py`;
- verify imports from `requirements.txt`;
- confirm ignored sensitive/generated files are not staged;
- inspect the staged diff and README commands;
- confirm the branch is `main`.

Network inventory checks and real order submission are not part of publication
verification. The purchase endpoint will not be called.

## Git Remote Strategy

The current `origin` points to the source repository. It will be renamed to
`upstream`. A new `origin` will point to
`https://github.com/kkkksad/tenxunyun.git`. The current branch will be named
`main`, commits will be pushed with upstream tracking, and no force push will
be used.

If the target repository already has incompatible history, publication will
stop for review instead of overwriting it.
